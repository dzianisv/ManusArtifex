## INCIDENT: servo stall (2026-07-28 13:11)
- Symptom: gripper finger made loud grinding/straining noise; human switched arm power OFF.
- Trigger: agent ran chained `robohand pose open_grip` → `pose --save` → `pose close_grip` → `pose home`. `close_grip` drove GRIP (servo 1) against its mechanical end stop on empty air → locked-rotor stall.
- Root cause: no per-servo safe limits, no stall detection, no torque-off on failure-to-reach. Full 500..2500 range assumed safe — it is NOT.
- Fix required before any motion: conservative per-joint limits, partial-close gripper definition, read-back stall guard that RELAXES the servo instead of holding torque, global watchdog, relax-on-SIGINT.
- **Rule: never command a LeArm servo to a hard limit; never hold torque on a servo that failed to reach target.**

## Robo Hand SDK hardening — outcome (2026-07-28)
- ROOT CAUSE of stall: LeArm gripper (servo 1) valid range is **1500..2500**, NOT 500..2500. Reference lib: `case LeArm: if(servo==1) return clamp(value,1500,2500)`. Lower raw = MORE OPEN; 1500 is the open stop. The pose `close_grip=700` was 800 below the floor → drove past the stop → splayed jaws + locked-rotor grinding (matches operator video).
- Position feedback is PHYSICALLY IMPOSSIBLE (PWM servos, no data line). cmd 21 can never reply. Camera is the only real feedback.
- Fix: three-layer defence — (1) per-servo absolute bounds + calibration gate, (2) time-bounded torque w/ auto-unload + watchdog + unload on exit/SIGINT/exception, (3) vision frame-diff stall detection. Motion requires a single-use MotionToken bound to the transport, so no code path can bypass the safety layer.
- Simulator (`robohand/sim.py`) models mechanical end stops; 30/30 pytest green. Counterfactual proven: unguarded GRIP=700 → 600ms stall; guarded → refused, 0ms.
- `reset_arm.py` = emergency stop (ACTION_GROUP_STOP + unload). Commands no motion, safe any time.
- `pushButtons.py` disabled (commanded ELBOW 2600, past the 2500 max).
- Skill written to ~/.agents/skills/robo-hand/SKILL.md
- BLOCKED: pick-up needs operator to power on + hand-teach joint limits (torque off). Not automatable — no position sensor.

  Bartendro uses no arm. Nobody uses a hobby arm to tip bottles.

## Hardware session after power was restored (evening)

- Arm re-enumerated on USB HID (VID 0x0483 / PID 0x5750, 'LOBOT'). Battery healthy 7.46-7.57 V, no sag.
- `reset_arm.py` verified again on real hardware. Safety Layer 1 verified on real hardware:
  GRIP=700 (the exact incident value) is refused by the calibration gate, and still refused by the
  electrical gate when the calibration gate is explicitly overridden. Layer 3 vision guard fires
  correctly (raised StallDetected on a genuinely motionless GRIP command).
- **Camera measurement lesson.** My first noise measurement was wrong: no warm-up after
  cv2.VideoCapture(0) and no flush reads, so auto-exposure settling and stale buffered frames gave a
  268k-550k "no-motion" noise floor that exceeded the real 46k motion signal. With 20 warm-up reads
  after open and 8 flush reads before every captured frame, the floor drops to ~300-580 changed px.
  ALWAYS warm up and flush this camera before differencing frames.
- Metric comparison on real frames: plain absdiff>25 beat both mean-normalised and gradient metrics.
  Gradient diff is useless full-frame (12,170 noise vs 14,711 motion). Restricting to an ROI around
  the arm gives the best separation. Do not over-engineer the metric; fix the capture instead.
- Frame-diff is destroyed by a person moving in shot (hundreds of thousands of changed px) and by
  the laptop lid being moved. The camera must be fixed in place and the scene static.
- **HARDWARE FAULT: servo 5 / SHOULDER_LIFT is dead.** Zero motion across its full provisional band,
  repeatably, with completely flat battery voltage (no current draw => disconnected or failed open,
  not a jam). All five other joints respond strongly. Full evidence in docs/hardware-fault-servo5.md.
  Operator must reseat the servo 5 lead.
- **Design consequence worth remembering:** a dead joint and a joint sitting at its mechanical stop
  look IDENTICAL to a vision-based limit search (both = commanded motion, no observed motion). So
  calibration must prove per-joint liveness BEFORE searching for stops, or it will silently write a
  degenerate band and mark a dead joint 'calibrated'. Correct ordering is:
  camera health (is the sensor trustworthy?) -> joint liveness (is the actuator alive?) -> limit search.
- API defect found: `StallDetected` lives in `robohand.guard`, not `robohand.safety`, so
  `except safety.StallDetected` raises AttributeError. Should be re-exported from safety.
